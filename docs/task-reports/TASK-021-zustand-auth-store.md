# Task 021: Zustand 인증 상태 저장소 구현

**완료일**: 2025-01-20
**파일**: `frontend/src/stores/auth-store.ts`

## 무엇을 만들었나요?

사용자의 로그인 상태를 관리하는 "상태 저장소"를 만들었습니다. 이것은 마치 카페의 "회원 명찰 보관함"과 같은 역할을 합니다.

카페에 들어올 때 회원 명찰을 꺼내서 달면 "아, 이 분은 회원이시구나"라고 알 수 있고, 나갈 때 명찰을 반납하면 더 이상 회원 혜택을 받을 수 없습니다. 우리 앱에서도 마찬가지로:

- **로그인하면**: 사용자 정보(이름, 이메일)를 저장소에 보관
- **로그아웃하면**: 저장소를 비워서 "로그인 안 됨" 상태로 변경

## 왜 이렇게 만들었나요?

웹 앱에서 여러 화면(페이지)이 있는데, 모든 화면에서 "이 사용자가 로그인했는지?"를 알아야 합니다. 예를 들어:

- 대시보드 화면: 로그인한 사용자만 볼 수 있음
- 메뉴바: 로그인 여부에 따라 "로그인" 또는 "로그아웃" 버튼 표시

**Zustand**라는 도구를 선택한 이유:
1. 사용법이 아주 간단함 (코드가 짧고 이해하기 쉬움)
2. React와 잘 어울림
3. 필요한 기능만 딱 제공 (불필요하게 복잡하지 않음)

## 어떻게 동작하나요?

저장소는 5가지 정보를 관리합니다:

| 정보 | 설명 | 예시 |
|------|------|------|
| `user` | 로그인한 사용자 정보 | `{이름: "철수", 이메일: "cs@mail.com"}` |
| `isAuthenticated` | 로그인 여부 | `true` 또는 `false` |
| `isLoading` | 로딩 중인지 | 로그인 버튼 누른 후 처리 중 |
| `error` | 오류 메시지 | "비밀번호가 틀렸습니다" |
| `isInitialized` | 앱 시작 시 확인 완료 여부 | 새로고침 후 자동 로그인 체크 완료 |

## 테스트는 어떻게 했나요? (TDD)

**RED 단계**: 먼저 테스트 코드를 작성했습니다. 저장소가 없으니 당연히 실패합니다.

**GREEN 단계**: 테스트를 통과하도록 실제 저장소 코드를 작성했습니다.

총 10개의 테스트를 작성했습니다:
- 초기 상태 확인 (로그인 안 됨으로 시작)
- 사용자 설정/해제
- 로딩 상태 변경
- 오류 메시지 설정
- 로그아웃 기능
- 전체 초기화 기능

## 관련 개념

- **상태 관리(State Management)**: 앱 전체에서 공유되는 데이터를 한 곳에서 관리
- **JWT(JSON Web Token)**: 로그인 정보를 담은 암호화된 토큰 (쿠키에 저장됨)
- **HTTPOnly Cookie**: 보안을 위해 JavaScript로 접근할 수 없는 쿠키

## 주의사항

- 실제 JWT 토큰은 이 저장소에 저장되지 않습니다 (쿠키에 있음)
- 이 저장소는 UI 표시용 정보만 관리합니다
- 새로고침하면 저장소가 초기화되므로 서버에서 다시 확인해야 합니다
