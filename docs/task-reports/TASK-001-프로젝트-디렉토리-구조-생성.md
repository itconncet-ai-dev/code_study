# 작업 보고서: T001 & T001A - 프로젝트 디렉토리 구조 생성

**작업 번호**: T001, T001A
**작성일**: 2025-01-16
**상태**: 완료

## 무엇을 만들었나요?

AI 코드 학습 플랫폼의 기본 뼈대가 되는 폴더 구조를 만들었습니다. 마치 새 집을 지을 때 방의 위치와 용도를 먼저 정하는 것처럼, 프로젝트의 각 기능이 어디에 위치할지 미리 정해두었습니다.

## 왜 이렇게 구성했나요?

웹 애플리케이션은 크게 두 부분으로 나뉩니다:
- **backend/**: 서버 측 코드 (요리사가 주방에서 일하는 것처럼, 사용자가 보지 못하는 곳에서 데이터를 처리)
- **frontend/**: 사용자 화면 (식당의 홀처럼, 손님이 직접 보고 만지는 부분)
- **storage/**: 업로드된 파일 저장소 (창고처럼 물건을 보관)
- **docs/**: 문서 저장소 (작업 기록을 남기는 일지장)

## 어떻게 작동하나요?

폴더 구조는 다음과 같이 역할을 분담합니다:

```
backend/
├── src/models/      → 데이터 형태 정의 (예: 사용자, 프로젝트 등)
├── src/services/    → 비즈니스 로직 (실제 일을 처리하는 부분)
├── src/api/         → 외부와 통신하는 창구
└── tests/           → 코드가 잘 작동하는지 확인하는 테스트

frontend/
├── src/components/  → 재사용 가능한 UI 조각들
├── src/pages/       → 화면별 페이지
└── src/services/    → 서버와 통신하는 부분

docs/task-reports/   → 작업 완료 보고서 (지금 읽고 계신 문서!)
```

## 테스트 방법

디렉토리 생성 후 `find` 명령어로 전체 구조를 확인했습니다. 모든 폴더에 `.gitkeep` 파일을 추가하여 Git에서 빈 폴더도 추적되도록 했습니다.

## 수정된 파일

- 새로 생성: `backend/`, `frontend/`, `storage/`, `docs/` 및 하위 디렉토리 전체
- 각 디렉토리에 `.gitkeep` 파일 추가

## 관련 개념

- **폴더 구조**: 프로젝트의 설계도. 잘 정리된 구조는 나중에 코드를 찾고 수정하기 쉽게 만듭니다.
- **.gitkeep**: Git은 빈 폴더를 추적하지 않아서, 빈 파일을 넣어 폴더를 유지합니다.

## 주의사항

- 폴더 이름을 변경하면 나중에 설정해야 할 경로들도 모두 바꿔야 합니다.
- `storage/uploads/`에는 사용자 파일이 저장되므로 `.gitignore`에 추가 필요합니다.
