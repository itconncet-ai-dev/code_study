# Task T061 - Task SQLAlchemy 모델 생성

**완료일**: 2025-01-24
**작성자**: Claude Opus 4.5

## 무엇을 만들었나요?

이번 작업에서는 **Task(학습 태스크)** 데이터베이스 모델을 만들었습니다. Task는 사용자가 업로드한 코드 파일 하나를 학습하기 위한 단위입니다. 마치 학교에서 한 과목의 하나의 단원을 공부하는 것과 비슷하다고 생각하면 됩니다.

예를 들어, "Python으로 만든 계산기 코드"를 업로드하면 하나의 Task가 만들어지고, 이 Task 안에서 AI가 설명 문서를 만들어주고, 연습 문제를 제공해주는 거죠.

## 왜 이렇게 만들었나요?

Task 모델은 몇 가지 중요한 특징이 있습니다:

1. **순차적 번호 부여**: 프로젝트 안에서 Task 1, Task 2, Task 3... 이런 식으로 자동으로 번호가 붙습니다. 노트에 페이지 번호를 매기는 것처럼 순서가 명확해집니다.

2. **소프트 삭제**: Task를 삭제해도 바로 사라지지 않고 30일 동안 휴지통에 보관됩니다. 실수로 삭제해도 복구할 수 있어요! 스마트폰의 "최근 삭제된 사진" 앨범과 같은 개념입니다.

3. **프로젝트와 연결**: 모든 Task는 반드시 하나의 프로젝트에 속합니다. 책이 챕터들로 구성되듯, 프로젝트가 Task들로 구성되는 구조입니다.

## 어떻게 동작하나요?

Task 모델은 다음과 같은 정보를 저장합니다:

- `id`: 고유 식별자 (UUID 형식)
- `project_id`: 소속 프로젝트
- `task_number`: 프로젝트 내 순번 (1, 2, 3...)
- `title`: 태스크 제목 (최소 5자)
- `description`: 설명 (선택, 최대 500자)
- `upload_method`: 업로드 방식 (file, folder, paste)
- `deletion_status`: 삭제 상태 (active, trashed)

## TDD 방식으로 어떻게 테스트했나요?

TDD(테스트 주도 개발)을 따라서 진행했습니다:

1. **RED 단계**: 먼저 20개의 테스트를 작성했습니다. 모델이 아직 없으니 당연히 모든 테스트가 실패합니다.

2. **GREEN 단계**: Task 모델을 구현했습니다. 모든 필드, 관계, 메서드를 추가한 후 테스트를 다시 실행하니 20개 모든 테스트가 통과했습니다.

3. **REFACTOR 단계**: 코드가 깔끔해서 별도 리팩토링은 필요하지 않았습니다.

## 관련 개념

- **SQLAlchemy ORM**: Python에서 데이터베이스를 쉽게 다루게 해주는 도구
- **UUID**: 전 세계에서 유일한 식별자를 만드는 방법
- **Foreign Key**: 다른 테이블의 데이터와 연결하는 방법
- **Soft Delete**: 데이터를 즉시 삭제하지 않고 휴지통에 보관하는 패턴

## 주의할 점

- Task 번호는 한번 부여되면 변경할 수 없습니다 (immutable)
- 같은 프로젝트 내에서 Task 번호는 중복될 수 없습니다
- 프로젝트가 삭제되면 해당 프로젝트의 모든 Task도 함께 삭제됩니다 (CASCADE)
