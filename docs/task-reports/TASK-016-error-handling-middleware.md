**날짜**: 2025-01-20

## 무엇을 만들었나요?

API 서버에서 발생하는 모든 에러를 일관된 형식으로 처리하는 시스템을 만들었어요. 마치 회사에서 모든 문서를 같은 양식으로 작성하는 것처럼, 우리 API도 모든 에러 메시지를 같은 형식으로 응답해요.

## 왜 이렇게 만들었나요?

여러분이 인터넷 쇼핑을 할 때, 어떤 사이트는 "에러가 발생했습니다"라고만 하고, 어떤 사이트는 "비밀번호가 틀렸습니다"라고 친절히 알려주잖아요? 우리 서비스는 항상 친절하게 무엇이 문제인지 알려주도록 했어요.

### 주요 에러 종류

1. **인증 에러 (Auth)**: 로그인이 안 됐거나, 권한이 없을 때
   - 예: "로그인이 필요합니다", "비밀번호가 틀렸습니다"

2. **찾을 수 없음 (NotFound)**: 요청한 자료가 없을 때
   - 예: "프로젝트를 찾을 수 없습니다"

3. **입력 오류 (Validation)**: 사용자가 잘못된 정보를 입력했을 때
   - 예: "이메일 형식이 올바르지 않습니다"

4. **파일 오류 (File)**: 업로드한 파일에 문제가 있을 때
   - 예: "파일이 10MB를 초과했습니다"

5. **서버 오류 (Internal)**: 서버에 문제가 생겼을 때
   - 예: "일시적인 오류가 발생했습니다"

## 어떻게 동작하나요?

도서관 사서를 생각해 보세요. 손님이 책을 요청하면:

1. 책이 있으면 → 책을 찾아줌 (정상 응답)
2. 책이 없으면 → "죄송합니다, 그 책은 없어요" (NotFoundError)
3. 회원 전용 책인데 비회원이면 → "회원만 볼 수 있어요" (ForbiddenError)
4. 사서가 갑자기 아프면 → "잠시 후에 다시 와주세요" (InternalError)

우리 코드도 이렇게 상황에 맞는 안내를 해줍니다.

## 에러 응답 형식

```json
{
  "success": false,
  "error": "RESOURCE_NOT_FOUND",
  "message": "프로젝트를 찾을 수 없습니다",
  "request_id": "abc-123-def",
  "timestamp": "2025-01-20T10:30:00Z",
  "path": "/api/v1/projects/123"
}
```

- **success**: 항상 false (에러니까요)
- **error**: 에러 종류 코드 (프로그램이 이해하는 코드)
- **message**: 사람이 읽을 수 있는 설명
- **request_id**: 문제 추적용 고유 번호 (고객센터에서 확인할 때 사용)
- **timestamp**: 에러 발생 시간
- **path**: 어느 주소에서 에러가 났는지

- **예외 처리**: 프로그램에서 예상치 못한 상황을 대처하는 방법
