# TASK-004: Docker Compose 설정 구성

**완료일**: 2025-01-16
**상태**: 완료

## 무엇을 만들었나요?

Docker Compose 설정 파일을 만들어서 개발할 때 필요한 두 가지 중요한 프로그램을 쉽게 실행할 수 있게 했어요.

**비유로 설명하면**: 식당에서 요리를 할 때 냉장고(PostgreSQL)와 전자레인지(Redis)가 필요하죠? Docker Compose는 이런 주방 도구들을 한 번에 설치하고 켤 수 있는 "스마트 주방 시스템"이에요.

## 왜 이렇게 만들었나요?

### PostgreSQL 15 선택 이유
- **JSONB 지원**: 7장으로 구성된 학습 문서를 JSON 형식으로 저장할 수 있어요
- **안정성**: 은행에서도 쓸 만큼 데이터를 안전하게 보관해요
- **Alpine 버전**: 파일 크기가 작아서 빠르게 다운로드할 수 있어요

### Redis 7 선택 이유
- **Celery 메시지 브로커**: AI 문서 생성 같은 오래 걸리는 작업을 백그라운드에서 처리할 때 필요해요
- **캐싱**: 자주 사용하는 데이터를 임시로 저장해서 빠르게 불러올 수 있어요
- **AOF 모드**: 정전되어도 데이터가 사라지지 않게 디스크에 저장해요

## 어떻게 테스트했나요?

1. **파일 생성 확인**: docker-compose.yml 파일이 올바른 YAML 형식으로 작성됨
2. **서비스 구성 확인**: PostgreSQL 15, Redis 7 버전 명시
3. **환경변수 설정**: .env 파일로 비밀번호 등을 외부에서 관리할 수 있게 함
4. **헬스체크 설정**: 서비스가 정상 작동하는지 자동으로 확인하는 기능 포함
5. **볼륨 설정**: 컨테이너를 재시작해도 데이터가 유지됨

## 수정한 파일들

| 파일 | 변경 내용 |
|------|-----------|
| `docker-compose.yml` | 새로 생성 - PostgreSQL, Redis 서비스 정의 |
| `.dockerignore` | 새로 생성 - Docker 빌드 시 제외할 파일 목록 |
| `backend/scripts/init-db/README.md` | 새로 생성 - DB 초기화 스크립트 폴더 설명 |

## 사용 방법

```bash
# 서비스 시작 (백그라운드 실행)
docker-compose up -d

# 로그 확인
docker-compose logs -f

# 서비스 중지
docker-compose down

# PostgreSQL 접속 테스트
docker exec -it code_learning_postgres psql -U code_learning -d code_learning_db

# Redis 접속 테스트
docker exec -it code_learning_redis redis-cli ping
```

## 관련 개념

- **컨테이너(Container)**: 프로그램을 독립된 상자에 넣어서 실행하는 기술. 다른 컴퓨터에서도 똑같이 작동해요.
- **볼륨(Volume)**: 컨테이너의 데이터를 컴퓨터에 저장하는 공간. USB처럼 데이터를 보관하는 역할이에요.
- **네트워크(Network)**: 컨테이너들이 서로 대화할 수 있는 통로예요.

## 주의사항

- 프로덕션 환경에서는 반드시 `.env` 파일에서 안전한 비밀번호를 설정해야 해요
- Docker가 설치되어 있어야 `docker-compose` 명령어가 작동해요
- 포트 5432, 6379가 다른 프로그램에서 사용 중이면 충돌이 발생할 수 있어요
