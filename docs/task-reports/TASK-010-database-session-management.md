# T010: 데이터베이스 세션 관리 구현

**작성일**: 2025-01-19
**상태**: 완료

## 무엇을 만들었나요?

데이터베이스와 대화하는 "전화 연결" 시스템을 만들었습니다. 웹사이트가 사용자 정보나 프로젝트 데이터를 저장하고 불러오려면 데이터베이스와 연결해야 하는데, 이 연결을 효율적으로 관리하는 코드입니다.

마치 은행 창구를 생각해보세요. 고객(웹사이트)이 은행(데이터베이스)에서 거래를 하려면 창구 직원(세션)과 대화해야 합니다. 한 명의 직원이 모든 고객을 처리하면 너무 느리니까, 여러 창구를 열어두고 필요할 때 사용하는 것처럼요.

## 왜 이렇게 만들었나요?

1. **비동기(async) 방식 사용**: 한 고객이 긴 업무를 처리하는 동안 다른 창구에서 다른 고객을 처리할 수 있게 했습니다. 이렇게 하면 웹사이트가 더 빠르게 응답합니다.

2. **연결 풀링(Connection Pooling)**: 매번 새 창구를 열고 닫는 대신, 미리 5개의 창구를 열어두고 재사용합니다. 새 창구를 여는 데 시간이 걸리니까, 미리 준비해두면 훨씬 빠릅니다.

3. **자동 정리**: 거래가 끝나면 창구를 자동으로 닫아서 다음 고객이 사용할 수 있게 합니다.

## 어떻게 작동하나요?

```python
# FastAPI 엔드포인트에서 사용할 때
@app.get("/users")
async def get_users(db: AsyncSession = Depends(get_db)):
    # db가 자동으로 세션을 받아서 사용
    # 함수가 끝나면 자동으로 정리됨
```

웹사이트 코드에서 `get_db`를 사용하면:
1. 미리 준비된 연결 풀에서 세션을 하나 가져옴
2. 데이터베이스 작업 수행
3. 성공하면 변경사항 저장, 실패하면 취소
4. 세션을 풀에 반환

## 테스트는 어떻게 했나요? (TDD 과정)

**빨간불 (RED)**: 먼저 10개의 테스트를 작성했습니다
- 엔진이 제대로 생성되는지
- asyncpg 드라이버를 사용하는지
- 세션 팩토리가 올바르게 설정되는지
- get_db가 세션을 반환하는지
- 연결 풀이 설정되는지

**초록불 (GREEN)**: 테스트를 통과하는 최소한의 코드 작성

**리팩터 (REFACTOR)**: `__init__.py` 업데이트로 import 정리

## 수정한 파일들

| 파일 | 변경 내용 |
|------|----------|
| `backend/src/db/session.py` | 새로 생성 - 핵심 세션 관리 코드 |
| `backend/src/db/__init__.py` | 수정 - 모듈 내보내기 추가 |
| `backend/tests/unit/test_db_session.py` | 새로 생성 - 10개 테스트 |
| `backend/tests/conftest.py` | 수정 - db_session 픽스처 추가 |

## 관련 개념

- **SQLAlchemy 2.0**: Python에서 가장 인기있는 데이터베이스 도구
- **asyncpg**: PostgreSQL용 초고속 비동기 드라이버
- **의존성 주입(Dependency Injection)**: FastAPI가 필요한 것을 자동으로 제공하는 패턴

## 주의할 점

- 환경변수로 `DATABASE_URL`이나 개별 PostgreSQL 설정을 해야 함
- 실제 데이터베이스가 없어도 코드는 로드되지만, 연결 시도 시 에러 발생
- `expire_on_commit=False`가 중요 - 비동기 환경에서 객체 접근 문제 방지
