## 무엇을 만들었나요?

사용자의 비밀번호를 안전하게 저장하기 위한 **비밀번호 해싱 유틸리티**를 만들었습니다.

쉽게 설명하면, 비밀번호를 금고에 넣는 것과 비슷합니다. 원래 비밀번호를 그대로 저장하면 누군가 데이터베이스를 훔쳐갔을 때 모든 비밀번호가 노출됩니다. 하지만 해싱을 하면 비밀번호가 복잡한 문자열로 변환되어, 원래 비밀번호를 알아낼 수 없습니다.

### 주요 기능

1. **`hash_password()`** - 비밀번호를 해시로 변환
2. **`verify_password()`** - 입력한 비밀번호가 저장된 해시와 일치하는지 확인
3. **`PasswordHasher`** - 객체 지향 방식의 해싱 도구
4. **`PasswordSettings`** - 환경 변수로 해싱 강도 설정

---

## 왜 이 방식을 선택했나요?

### bcrypt 알고리즘 선택 이유

1. **시간이 지나도 안전함**: bcrypt는 "라운드"라는 개념으로 해싱 속도를 조절합니다. 컴퓨터가 빨라지면 라운드 수를 높여서 보안을 유지할 수 있습니다.

2. **자동 소금(salt) 추가**: 같은 비밀번호라도 매번 다른 해시가 생성됩니다. 마치 요리에 소금을 조금씩 다르게 넣는 것처럼, 해커가 미리 계산해둔 해시 테이블(레인보우 테이블)을 사용할 수 없게 만듭니다.

3. **업계 표준**: 구글, 페이스북 등 대형 서비스들도 bcrypt를 사용합니다.

### passlib 대신 bcrypt 직접 사용

처음에는 passlib 라이브러리를 사용했지만, Python 3.14와의 호환성 문제가 있었습니다. 그래서 bcrypt 라이브러리를 직접 사용하는 방식으로 변경했습니다. 이렇게 하면 더 단순하고 의존성도 줄어듭니다.

## 어떻게 동작하나요?

### 비밀번호 저장 과정

```
사용자 입력: "MyPassword123!"
     ↓
UTF-8 인코딩: b"MyPassword123!"
     ↓
소금 생성: 무작위 16바이트
     ↓
해싱 (12라운드): 약 0.3초 소요
     ↓
결과: "$2b$12$xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

### 비밀번호 확인 과정

```
사용자 입력: "MyPassword123!"
저장된 해시: "$2b$12$xxx..."
     ↓
같은 소금으로 해싱
     ↓
결과 비교 (시간 균등 비교로 타이밍 공격 방지)
     ↓
True (일치) 또는 False (불일치)
```

## 관련 개념

### 해싱 vs 암호화

- **해싱**: 단방향 변환. 원래 값을 복원할 수 없음 (비밀번호에 적합)
- **암호화**: 양방향 변환. 키로 복원 가능 (개인정보에 적합)

### 소금(Salt)

해시에 무작위 데이터를 추가하는 기법입니다. 같은 비밀번호라도 다른 해시가 생성되어, 미리 계산된 해시 테이블 공격을 방지합니다.

### 라운드(Rounds/Cost Factor)

해싱 연산을 반복하는 횟수입니다. 라운드가 높을수록:
- 해싱 시간 증가 (기하급수적)
- 보안 강화 (무차별 대입 공격 어려움)
- 권장: 개발 4, 프로덕션 12

## 주의사항

1. **72바이트 제한**: bcrypt는 72바이트 이상의 비밀번호를 자동으로 잘라냅니다. 이는 bcrypt의 설계상 제한으로, 보안상 문제는 없습니다.

2. **환경 변수 설정**: 프로덕션에서는 `BCRYPT_ROUNDS=12` 이상을 권장합니다.

3. **해시 저장**: 해시는 60자 고정 길이입니다. 데이터베이스 컬럼을 `VARCHAR(60)` 또는 그 이상으로 설정하세요.
