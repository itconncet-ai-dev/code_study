## 무엇을 만들었나요?

사용자 인증을 담당하는 `UserService`를 만들었습니다. 이 서비스는 마치 아파트 경비실과 같은 역할을 합니다.

- **회원가입 (register)**: 새 입주민 등록하기
- **로그인 (login)**: 신분증 확인하고 출입 허용하기
- **사용자 조회 (get_by_id, get_by_email)**: 입주민 정보 찾기

---

## 왜 이렇게 만들었나요?

### 1. 보안이 가장 중요합니다

비밀번호는 절대 그대로 저장하면 안 됩니다. 마치 집 열쇠를 현관문에 걸어두는 것과 같기 때문이죠. 그래서 `bcrypt`라는 암호화 기술로 비밀번호를 "해시"합니다. 해시된 비밀번호는 원래 비밀번호로 되돌릴 수 없어서 안전합니다.

### 2. 같은 오류 메시지를 사용합니다

로그인 실패 시 "이메일이 없습니다" 또는 "비밀번호가 틀렸습니다"라고 구체적으로 알려주면, 해커가 어떤 이메일이 등록되어 있는지 알아낼 수 있습니다. 그래서 항상 "이메일 또는 비밀번호가 올바르지 않습니다"라고만 알려줍니다.

### 3. 입력값 검증은 필수입니다

- **이메일 형식 확인**: `user@example.com` 형태인지 검사
- **비밀번호 길이 확인**: 최소 8자 이상 필요

---

## 어떻게 작동하나요?

### 회원가입 과정

```
1. 사용자가 이메일과 비밀번호 입력
2. 이메일 형식이 올바른지 확인
3. 비밀번호가 8자 이상인지 확인
4. 이미 같은 이메일로 가입한 사람이 있는지 확인
5. 비밀번호를 암호화
6. 데이터베이스에 새 사용자 저장
7. 저장된 사용자 정보 반환
```

### 로그인 과정

```
1. 사용자가 이메일과 비밀번호 입력
2. 해당 이메일의 사용자 찾기
3. 없으면 → "이메일 또는 비밀번호가 올바르지 않습니다" 오류
4. 있으면 → 비밀번호 확인
5. 틀리면 → 같은 오류 메시지
6. 맞으면 → 마지막 로그인 시간 업데이트
7. 사용자 정보 반환
```

## 관련 개념들

- **bcrypt**: 비밀번호 암호화 알고리즘. 단방향 해시라서 복호화 불가능
- **AsyncSession**: 비동기 데이터베이스 세션. 여러 요청을 동시에 처리 가능
- **ValidationError**: 입력값이 올바르지 않을 때 발생하는 오류
- **AlreadyExistsError**: 이미 존재하는 리소스를 만들려 할 때 발생하는 오류
- **InvalidCredentialsError**: 인증 실패 시 발생하는 오류

---

## 주의할 점

1. **비밀번호 최소 길이**: 현재는 8자로 설정되어 있습니다. 보안 요구사항에 따라 조정 가능합니다.
2. **이메일 형식 검증**: 기본적인 형식만 확인합니다. 실제로 존재하는 이메일인지는 확인하지 않습니다.
3. **로그아웃**: 이 서비스에서는 로그아웃 로직이 포함되지 않았습니다. 토큰 관리는 T026의 `TokenService`에서 담당합니다.
