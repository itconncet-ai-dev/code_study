# TASK-017: Celery 앱과 Redis 연결 설정

**파일**: `backend/src/tasks/celery_app.py`
**날짜**: 2025-01-20
**상태**: 완료 ✅

## 무엇을 만들었나요?

Celery라는 비동기 작업 처리 시스템과 Redis 메시지 브로커를 연결하는 설정을 만들었어요. 마치 식당에서 주문을 받는 카운터(Redis)와 주방에서 요리하는 셰프들(Celery Worker)을 연결하는 시스템이에요.

## 왜 이렇게 만들었나요?

우리 서비스에서 AI가 학습 문서를 만드는 데는 최대 3분이 걸릴 수 있어요. 만약 사용자가 문서 생성을 요청할 때마다 3분 동안 웹페이지가 멈춰있다면 정말 불편하겠죠?

그래서 다음과 같은 방식으로 처리해요:

1. 사용자가 코드를 업로드하면 → "알겠습니다! 만들고 있을게요~" 바로 응답
2. 뒤에서 Celery 워커가 열심히 문서를 만듦
3. 사용자는 다른 일을 하다가 나중에 완성된 문서를 확인

이런 방식을 "비동기 처리"라고 해요.

## 어떻게 동작하나요?

### 음식점 비유

1. **손님(사용자)**: "토마토 파스타 주세요!"
2. **카운터 직원(Redis 브로커)**: 주문서를 받아서 주방에 전달
3. **주방 셰프(Celery Worker)**: 주문서를 보고 요리 시작
4. **주문 번호판(Result Backend)**: 요리가 완성되면 번호가 표시됨
5. **손님**: 번호가 뜨면 음식을 가져감

우리 시스템도 똑같이 동작해요:
- **Redis 브로커**: 작업 요청을 전달하는 메시지 큐 (데이터베이스 1번)
- **Redis 백엔드**: 작업 결과를 저장하는 곳 (데이터베이스 2번)
- **Celery Worker**: 실제로 작업을 수행하는 프로세스

### 설정된 작업 큐

```text
┌─────────────────────────────────────────────────────────────┐
│                        작업 큐 구조                           │
├─────────────────────────────────────────────────────────────┤
│  default           : 일반적인 작업                            │
│  document_generation: AI 학습 문서 생성 (최대 3분)             │
│  practice_generation: 연습 문제 생성                          │
│  cleanup           : 휴지통 정리 (30일 지난 항목 삭제)          │
└─────────────────────────────────────────────────────────────┘
```

## 주요 설정 값

| 설정 | 값 | 설명 |
|------|-----|------|
| 브로커 URL | redis://localhost:6379/1 | 작업 요청을 전달하는 곳 |
| 결과 백엔드 | redis://localhost:6379/2 | 작업 결과를 저장하는 곳 |
| 작업 시간 제한 | 300초 (5분) | 하나의 작업 최대 실행 시간 |
| 결과 만료 | 24시간 | 결과 데이터 보관 기간 |
| 직렬화 형식 | JSON | 데이터 전송 형식 |

## 관련 개념

- **비동기 처리**: 작업을 요청하고 결과를 나중에 받는 방식 (기다리지 않아도 됨)
- **메시지 큐**: 작업 요청을 순서대로 줄 세워서 처리하는 시스템
- **워커 프로세스**: 실제로 작업을 수행하는 백그라운드 프로그램
- **직렬화**: 데이터를 전송 가능한 형태(JSON)로 변환하는 것

## 사용 방법

```bash
# 백엔드 디렉토리에서 Celery 워커 시작
cd backend
celery -A src.tasks.celery_app worker --loglevel=info

# 예약 작업을 위한 Beat 스케줄러 시작
celery -A src.tasks.celery_app beat --loglevel=info
```

## 주의사항

- Redis 서버가 먼저 실행되어 있어야 해요 (`docker-compose up redis`)
- 프로덕션에서는 반드시 Redis 비밀번호를 설정해야 해요
- 워커 프로세스가 갑자기 죽으면 작업이 재시도됨 (task_reject_on_worker_lost=True)
